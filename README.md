# 📊 InvestTracker

> Форк [`Relff/t-invest-portfolio-tracker`](https://github.com/Relff/t-invest-portfolio-tracker) с доработками для учёта общего капитала: брокерский портфель T-Invest + ручные денежные активы, физическая валюта и рублёвые накопительные счета.

Проект работает в **Google Sheets + Google Apps Script** и синхронизирует брокерские позиции через **T-Invest API**. Основная идея форка — сохранить исходную аналитику и ребалансировку, но добавить нормальный учёт капитала вне брокера и сделать показатели доходности более понятными.

> **Важно:** проект не совершает сделки. Для T-Invest используется токен с правами **только на чтение**.

## 🔀 Что изменено в этом форке

### 💵 Учёт наличных и денежных активов

Добавлен отдельный модуль [`Code/cash.js`](Code/cash.js) и лист **`💵 Наличные`**.

Слева находится ручной журнал операций:

| Дата | Операция | Актив | Количество | Курс сделки ₽ | Сумма ₽ | Комментарий |
|---|---|---|---:|---:|---:|---|
| 13.11.2024 | Покупка | USD | 100 | 104.30 | 10 430 | |
| 09.10.2026 | Пополнение | Вклад RUB | 20 000 | 1 | 20 000 | Резерв |
| 31.10.2026 | Проценты | Вклад RUB | 500 | 1 | 500 | 13.5% годовых |

Поддерживаемые операции:

- `Покупка`
- `Продажа`
- `Пополнение`
- `Снятие`
- `Проценты`

Ручной журнал **никогда не очищается и не перезаписывается скриптом**.

Справа автоматически строится сводка:

| Поле | Что показывает |
|---|---|
| Актив | USD, EUR, Вклад RUB, Сейф RUB и т.д. |
| Текущий курс | ручной курс для валют, `1` для RUB |
| Кол-во | остаток с учётом покупок/продаж/снятий |
| На сумму | текущая стоимость в рублях |
| % от наличных | доля актива внутри денежной части |
| Средний курс покупки | средняя себестоимость |
| P/L ₽ | нереализованный курсовой результат |
| P/L % | нереализованный результат в процентах |
| Реализ. P/L | результат завершённых продаж |
| Проценты / доход | накопленный доход от операций `Проценты` |

Базовая валюта определяется по последнему слову в названии актива:

```text
USD        → USD
EUR        → EUR
Вклад RUB  → RUB
Сейф RUB   → RUB
```

Это позволяет различать несколько рублёвых денежных активов без отдельного поля «место хранения».

### 🧮 Наличные участвуют в общей структуре портфеля

Ручные денежные активы учитываются на Dashboard как категория **`Кэш`**.

Они:
- входят в общую структуру капитала;
- учитываются в Health Check концентрации;
- учитываются при ребалансировке классов активов;
- **не включаются в XIRR брокерского портфеля и сравнение с IMOEX**.

Это сделано намеренно: результат брокерской стратегии не должен смешиваться с валютой и резервами вне брокера.

## 📈 Аналитика доходности

### XIRR с выбранной даты

В `⚙️ Настройки` можно задать:

```text
XIRR — считать с даты
```

Например:

```text
22.06.2026
```

Это позволяет отделить текущую инвестиционную стратегию от старых пополнений, выводов и экспериментов.

### Фактический результат периода

Кроме годового XIRR Dashboard показывает простой фактический результат:

```text
Фактический результат периода:
▲ 3.6% · +3 961 ₽
```

Расчёт:

```text
текущая стоимость брокерского портфеля
+ выводы за период
− пополнения за период
```

Это **не annualized return**, а фактический результат выбранного периода.

### Исправлен benchmark относительно IMOEX

Сравнение с IMOEX использует ту же стартовую дату, что и XIRR, и учитывает пополнения/выводы. Ручной кэш в benchmark не включается.

## 📊 Dashboard

В форке исправлены и доработаны:

- корректная обработка процентов из Google Sheets (`40%` больше не превращается в `0.4%`);
- учёт `_Дан_Валюта`, включая золото;
- исключение дублирующей RUB-позиции;
- полные названия акций без искусственного обрезания;
- динамическое чтение Config без зависимости от жёстких номеров строк;
- корректная работа специальных категорий;
- интеграция ручного кэша;
- обновление всех дополнительных аналитических секций при `🚀 Синхронизировать + обновить всё`.

Полная синхронизация обновляет в том числе:

- среднюю цену и P/L;
- Yield on Cost;
- ЛДВ;
- ИИС-3, если настроен;
- секторную диверсификацию, если настроена;
- прогресс к цели;
- ожидаемый доход;
- календарь выплат;
- Health Check и уведомления.

## 🏦 Дисциплина пополнений

Исправлено отображение месяцев на Dashboard: значения записываются как текст, чтобы Google Sheets не превращал часть месяцев в локализованные даты вида `дек. 2025`.

Цвет суммы:
- 🟢 положительное — чистое пополнение;
- 🔴 отрицательное — чистый вывод;
- серое — операций не было.

## 💰 Ребалансировка

Логика upstream сохранена: калькулятор распределяет новое пополнение между недовзвешенными классами и активами с учётом лотности.

Для ручных денежных активов:
- категория `Кэш` участвует в целевой структуре;
- если кэша уже больше цели, новые деньги туда не направляются;
- отдельные активы можно исключать чекбоксом `Пропустить`.

Красный статус означает **отклонение от целевой структуры**, а не рекомендацию срочно продавать актив.

## 🔐 Безопасность

Рекомендуется использовать T-Invest API token с правами **только на чтение**.

Токен хранится в:

```text
Apps Script
→ Project Settings
→ Script Properties
→ TINKOFF_TOKEN
```

Токен **не должен находиться в GitHub-репозитории**.

В коде нет логики:
- выставления заявок;
- отмены заявок;
- покупки/продажи;
- вывода денежных средств.

### SSL и личный proxy

Если прямой запрос из Google Apps Script к T-Invest падает из-за TLS/SSL, можно использовать личный proxy из [`PROXY-SETUP.md`](PROXY-SETUP.md).

Proxy должен принадлежать самому пользователю. Проверка TLS не отключается.

## ⚙️ Установка

### Через исходную Google Sheet

1. Создать копию таблицы из upstream-проекта.
2. Получить **Script ID** своей копии:
   `Расширения → Apps Script → Настройки проекта`.
3. Клонировать этот форк:

```bash
git clone https://github.com/TRAIANUSssS/InvestTracker.git
cd InvestTracker
```

4. Авторизовать `clasp`:

```bash
npx @google/clasp login
```

5. Создать локальный `.clasp.json`:

```json
{
  "scriptId": "YOUR_SCRIPT_ID",
  "rootDir": "Code"
}
```

`.clasp.json` уже исключён через `.gitignore`.

6. Проверить файлы:

```bash
npx @google/clasp show-file-status
```

7. Отправить код в Apps Script:

```bash
npx @google/clasp push
```

8. Добавить `TINKOFF_TOKEN` в Script Properties.
9. Перезагрузить Google Sheet и выполнить:

```text
Tinkoff → 🚀 Синхронизировать + обновить всё
```

## ⚠️ Известные ограничения

### Будущие дивиденды

Текущая логика дивидендов в основном использует историю `GetDividends`.

Из-за этого уже объявленный дивиденд, дата которого ещё не наступила, иногда может отсутствовать в:

```text
💵 Ожидаемый доход
📅 Календарь выплат
```

В таком случае его можно временно переопределить вручную через блок дивидендов в `⚙️ Настройки`.

Планируемое улучшение: сначала использовать объявленные будущие выплаты, а исторический CAGR — только как fallback.

### Текущие курсы ручных валют

Для USD/EUR и других ручных денежных активов текущий курс пока задаётся пользователем вручную в сводке `💵 Наличные`.

RUB-активы автоматически используют курс `1`.
